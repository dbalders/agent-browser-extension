# agent-browser-extension 0.1.0 — developer preview

An independent Chrome extension and local browser bridge maintained by David Balderston. It connects MCP-compatible agents and HTTP clients to Chrome on the user's computer. This first public release starts with a reviewed source snapshot and fresh Git history.

## Included

- 39 tools for tab discovery, ownership, background tasks, page snapshots, semantic targeting, forms, screenshots, frames, files, dialogs and bounded diagnostics.
- Ask-first website permissions, separate debugging grants, task status indicators, Stop controls and cleanup that preserves existing user tabs and retained results.
- Authenticated loopback HTTP/WebSocket transport and an MCP server over stdio.
- Apache-2.0 source, dependency license inventory, source archive and SHA-256 checksums.

## Install

Requires Chrome 125+ and Node 22.12+ on the supported 22.x, 24.x or 26+ lines.

Download and extract `agent-browser-extension-0.1.0-source.tar.gz` from the [release](https://github.com/dbalders/agent-browser-extension/releases/tag/v0.1.0), or clone the repository and check out `v0.1.0`. In the source directory:

```sh
npm ci
npm run build
node dist/cli.js serve
```

Keep that terminal running. In another terminal, run `node dist/cli.js pair` and `node dist/cli.js setup`. Load `dist/extension` using **Developer mode → Load unpacked** in `chrome://extensions`, enter the pairing details, and add the printed MCP configuration to your agent. See the [complete setup guide](../../README.md#local-setup).

Connection data uses `AGENT_BROWSER_HOME` or `~/.agent-browser-extension`. Earlier development builds may need fresh pairing. A shared explicit `--home` directory can be used by the bridge and all clients. The connection code grants access to the connected browser profile; keep it private.

## Verification scope

The [Check workflow](https://github.com/dbalders/agent-browser-extension/actions/workflows/check.yml) runs install, type checking, behavioral tests, build and release-hygiene checks on Linux with Node 22/24/26 and on macOS/Windows with Node 24. A separate Linux job runs the real extension in isolated Chromium and verifies a clean source-archive installation. Consult the run attached to the release commit for actual results.

The source archive includes a per-file `RELEASE-MANIFEST.json`; the separate `SHA256SUMS` verifies the downloadable archive. The archive excludes dependencies, browser profiles, credentials, generated builds, private test evidence and development history.

## Known limits

- This is a developer preview distributed as source. It is not a Chrome Web Store release or an npm package. Installation, bridge startup and updates are manual.
- Chrome and the bridge must run on the same computer. One profile connects to each bridge.
- Browser tests use isolated profiles and local fixtures; they do not establish compatibility with all websites, enterprise policies, agent applications or model providers. Windows/macOS unit checks are not real-browser proof on those platforms.
- CPU profiling depends on the Chrome build. The local Chrome for Testing 148 smoke captured real samples; unsupported builds report `PROFILE_UNAVAILABLE`. Document traces are not full browser/GPU traces.
- Agent/provider data handling is separate from local browser control. See [privacy](../privacy.md) and [security](../../SECURITY.md).
- More operational limits are in the [README](../../README.md#current-limits).

Use [Issues](https://github.com/dbalders/agent-browser-extension/issues) for support and the [private security form](https://github.com/dbalders/agent-browser-extension/security/advisories/new) for vulnerabilities.
